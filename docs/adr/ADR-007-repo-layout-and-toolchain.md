# ADR-007: Repo layout and toolchain

- Status: accepted
- Date: 2026-08-08

## Context

One public monorepo: Python domain and FastAPI service, React SPA (ADR-001), a
generated contract package (ADR-005), encrypted private data (ADR-002), governance
compiled by `aie`, and a demo mode a stranger can run. The old repo's structure lessons:
schema definitions triplicated because there was no shared package; scripts importing
each other via sys.path; content embedded in code.

## Layout

```
harrier/
  apps/web/                  # Vite React SPA, Feature-Sliced Design
  services/api/              # FastAPI service + harrier domain package
    src/harrier/             #   domain: tracker, screening, scoring, artifacts, outreach
    src/harrier_api/         #   API layer: routes, run manager, SSE, OpenAPI export
    src/harrier_cli/         #   CLI entry points (same domain code paths as the API)
    tests/
  packages/contract/         # openapi.json + generated TS types (committed, never hand-edited)
  config/                    # public config: feeds, schedule, data classification
  fixtures/                  # synthetic demo data, scrubbed importer recordings
  specs/                     # spec-gated backlog (approved: yes gates implementation)
  docs/                      # ADRs, architecture, plans
  .ai/                       # hand-edited governance sources (aie)
  .claude/, CLAUDE.md, AGENTS.md   # generated by aie sync, never hand-edited
  .github/workflows/
  justfile
```

One Python project (`services/api`) rather than a separate `packages/domain` Python
package: the domain, API, and CLI ship together, and splitting Python packaging across
the monorepo adds publishing ceremony with no consumer. The domain stays importable and
API-free as a package boundary inside the project (`harrier` imports nothing from
`harrier_api`); the import direction is lint-enforced (import-linter contract).

## Python toolchain

- **uv** for env and lockfile: fast, single tool, `uv sync` reproduces the env.
- **ruff** for lint and format (replaces flake8/black/isort in one).
- **pyright** in strict mode for type-checking: the Python analog of strict TS, and it
  runs fast enough for the turn-end gate. mypy rejected as the slower second choice.
- **pytest** over the old unittest style; behavior pins ported from the 22 old test
  files.
- Python 3.12 pinned in `.python-version`.

## TypeScript toolchain

- **pnpm** workspaces (`apps/web`, `packages/contract`).
- **Vite** + **vitest** + **React Testing Library**.
- **TypeScript strict** (`strict: true`, `noUncheckedIndexedAccess: true`).
- **ESLint** flat config with `typescript-eslint`, plus FSD boundary enforcement
  (`eslint-plugin-boundaries`); **Prettier** for format.
- Node LTS pinned in `.nvmrc` and `engines`.

## Pre-commit wiring

**lefthook** (fast, no Python-env coupling for a polyglot repo) running: gitleaks,
ruff check + format check, ESLint and Prettier on staged files, and the commit-msg
trailer check (`Spec: NNN` shape, mirroring the PreToolUse guard so plain terminal
commits are covered too). Heavier gates (pyright, tsc, tests, contract drift) run in
the turn-end hook and CI, not pre-commit, to keep commits fast.

## One-command dev up

**just** as the task runner (`justfile` at root):

- `just dev`: starts FastAPI (uvicorn reload) and Vite together (honcho or
  process-compose), real data mode if the local database exists (ADR-008).
- `just demo`: seeds a temp SQLite from `fixtures/`, starts the API in demo mode
  serving the built SPA; the stranger's one command.
- `just check`: the full local gate (both type-checks, both linters, both test suites,
  contract drift, `aie check`); identical to CI by construction: CI calls the same
  recipes.
- `just backup`, `just export`, `just schedule-install` wrap the flows from ADR-008,
  ADR-003, ADR-006.

## Consequences

- The tracker schema, the status lifecycle, and screening rules each get exactly one
  definition in `services/api/src/harrier/`, consumed by CLI, API, and scheduler.
- CI and local checks cannot drift because both invoke `just` recipes.
- Docker remains only for the demo path (optional), not the daily driver; launchd plus
  local processes are the production topology (ADR-006).
