# ADR-005: The API contract seam

- Status: accepted
- Date: 2026-08-08

## Context

Sorrel's governance anchors on `schema.graphql`: generated types make an invented field
a compile error, and a PreToolUse guard pauses edits to the contract. Harrier's analog
is the OpenAPI document generated from FastAPI. The requirement: an invented endpoint or
field becomes a type error before a human reads the diff, and contract drift fails CI.

Two drift directions must both fail:

1. Backend changed, generated client stale (client no longer matches the API).
2. Frontend invented an endpoint or field (compile error against the generated types).

## Contract source of truth

The FastAPI app is the source; the checked-in `packages/contract/openapi.json` is the
contract artifact. A deterministic export script (`services/api` exposes
`python -m harrier_api.export_openapi`) writes it with sorted keys and a pinned
`openapi` version so the diff is stable. Pydantic models give the schema real types;
`operation_id`s are explicit and stable because the generated client's names derive
from them.

## Codegen tool options

1. **openapi-typescript + openapi-fetch (recommended)**: generates a single `.d.ts` of
   types plus a tiny (~6 kB) runtime-typed fetch client. No classes, no per-endpoint
   generated functions to drift, no runtime validation layer to double-maintain. Paths
   and schemas are looked up by string literal, so an invented endpoint or field fails
   `tsc` exactly as required. SSE endpoints are consumed with native `EventSource`
   using generated event payload types.
2. **orval**: generates per-endpoint functions plus TanStack Query hooks. Attractive,
   but the generated hook layer couples codegen output to a specific query library
   version and produces much more generated surface to check in and re-review.
3. **@hey-api/openapi-ts**: capable successor to openapi-typescript-codegen; heavier
   generated client, plugin system in flux. More machinery than this contract needs.

Thin hand-written Query hooks over `openapi-fetch` keep the generated surface minimal
and the seam legible: generated types are the contract, hooks are app code.

## Where generated code lives

`packages/contract/`: `openapi.json` (exported artifact) and `src/schema.d.ts`
(generated types), both committed. The web app imports types only from
`@harrier/contract`. Committed rather than generated-on-install so that PR diffs show
contract changes in review, the same way Sorrel reviews `schema.graphql`.

## CI drift gate

One job, `contract-drift`:

1. Boot nothing; run the export script against the app import (no server needed).
2. Run `openapi-typescript` on the exported document.
3. `git diff --exit-code packages/contract/` fails the job if either artifact differs
   from HEAD.

Frontend type-check (`tsc --noEmit`) then enforces direction 2. The pre-edit guard from
the governance chain pauses on `packages/contract/**` (generated files are never
hand-edited; the guard makes the attempt loud).

## Decision

OpenAPI document exported deterministically from FastAPI, committed under
`packages/contract/` together with types generated by openapi-typescript; runtime calls
through openapi-fetch; drift fails CI via regenerate-and-diff.

## Consequences

- Adding an endpoint is a three-file diff (route, exported schema, generated types) and
  the review sees the contract change explicitly.
- The frontend cannot reference an endpoint or field that the backend does not declare;
  `tsc` fails first.
- No runtime request validation is added on the client; the server (Pydantic) remains
  the validator, and the types are trusted at the seam. Stated as a limitation.
- Python-side clients (none today) would consume the same committed document if ever
  needed.
