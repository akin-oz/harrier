# Spec 094: The browser works in a chosen search track, and manages tracks

## Problem

After spec 093 the command line can create an academic track (for example
university or research vacancies), name it with `--track`, and work in it.
The browser cannot. Every API route resolves the default track through
`get_scope` (`services/api/src/harrier_api/deps.py`, spec 092), no route
names another, and the web app shows the default track only. Spec 093 left
this out on purpose: "the API, the contract and the web track switcher" are
in its Out of scope list.

Four things are missing, and each is visible:

- **No route lists, creates or archives a track.** `harrier tracks list`,
  `tracks add` and `tracks archive` have no HTTP equivalent.
- **No request can say which track it means.** A second track's rows are
  unreachable from the browser, and nothing refuses a browser request that
  would run an industry-only operation on an academic track, because no such
  request can be made yet. The day one can, the refusal has to exist.
- **A job read over HTTP carries no track and no deadline.** `JobOut` predates
  both columns, so the browser cannot show the deadline the academic queue is
  ordered by, or flag one that has passed.
- **The manual add form has no deadline field.** `AddJobIn` predates
  migration 9.

## Scope

**Domain**

- `services/api/src/harrier/tracks.py`: the allowlist spec 093 put in
  `harrier_cli/main.py` (`TRACK_ALLOWLIST`, `TRACK_WRITES`) moves here as
  `NON_DEFAULT_OPERATIONS` and `WRITE_OPERATIONS`, so the CLI and the API
  read one list. Two read operations join it: `list` (the track's rows) and
  `counts` (its status counts), which the browser needs and the CLI reaches
  through `next` and `review`. The CLI imports the moved names; its behavior
  does not change.

**API** (`services/api/src/harrier_api/`)

- `deps.py`: `get_scope` takes an optional `track` query parameter, declared
  with the slug rule as its pattern, so it appears on every route that
  depends on `ScopeDep` in the generated contract. Absent means the default
  track, as today.
- `deps.py`: a route dependency `allowed_on_track(operation)` that refuses a
  non-default scope for an operation outside `NON_DEFAULT_OPERATIONS`, and an
  archived scope for an operation in `WRITE_OPERATIONS`.
- `app.py`, `capture_routes.py`, `outreach_routes.py`, `mail_routes.py`:
  every route that depends on `ScopeDep` declares its operation through that
  dependency. The mapping is the table under Behavior.
- New `tracks_routes.py`: `GET /tracks`, `GET /tracks/kinds`,
  `POST /tracks`, `POST /tracks/{slug}/archive`.
- `JobOut` gains `track`, `deadline` and `deadline_passed`. `AddJobIn` gains
  `deadline`.

**Contract**

- `packages/contract/openapi.json` and `packages/contract/src/schema.d.ts`,
  regenerated by `just contract`. A guarded path, approved under this spec.

**Web** (`apps/web/src/`)

- `shared/track/` (new): the selected track, read from and written to the
  `track` query string of the page URL, and the query-key prefix every data
  hook uses.
- `widgets/header/`: a track switcher listing live tracks, the selected one
  marked, with the track's kind beside its label.
- `features/tracks/` (new): the add form and the archive action.
- `pages/tracks/` (new): the tracks page, reached from the switcher.
- `pages/tracker/TrackerPage.tsx`, `features/tracker/AddJob.tsx`,
  `features/tracker/JobActions.tsx`: status labels from the selected track's
  kind, a deadline column and the passed flag, a deadline field on the add
  form on an academic track.
- `entities/job/`: the status pill takes its label from the track, a new
  deadline cell, and a deadline-led layout of the job table.
- `pages/apply/`, `pages/outreach/`, `pages/inbox/`, `features/apply/`: their
  query keys start with the selected track. Nothing else in them changes.
- `app/App.tsx`: the Apply, Outreach and Inbox sections, and the Operations
  section when spec 050 lands, are shown disabled on a non-default track,
  each with the sentence under Behavior.
- Tests beside each changed file.

**Design record**

- `apps/web/PRODUCT.md` (new, public): the product record the design work
  reads, written by `/impeccable init` on this branch. It describes the
  operator generically and holds no personal data (ADR-008). Added to this
  Scope during implementation; see the amendment.

**Not touched**: the schema, the CLI's behavior, the bookmarklet capture
route's track (it stays on the default track), the run manager, and every
route that does not read or write tracker rows (`/config`, `/health`,
`/session`, `/runs`).

## Behavior

### A request names its track

Every route that reads or writes tracker rows accepts `?track=<slug>`.

- Absent: the default track, exactly as today. A client that never sends the
  parameter sees no change, which is how the bookmarklet keeps working.
- A slug outside the rule: 422 from the schema, before the route runs.
- A well-formed slug that names no track: 404, with a detail naming the slug.
- The scope is resolved once per request, as spec 092 requires; the new
  parameter changes what it resolves to, not how often.

### One allowlist for both surfaces

On a non-default track a route runs only when its operation is in
`NON_DEFAULT_OPERATIONS`. Otherwise it answers 409 with the detail
`"<operation> is not available on track <slug>"`, before the route reads a
row. On an archived track, an operation in `WRITE_OPERATIONS` answers 409
with `"track <slug> is archived"`.

| Route | Operation | On a non-default track |
|---|---|---|
| `GET /jobs` | `list` | allowed |
| `GET /tracker/queue` | `next`, or `review` when `undecided=true` | allowed |
| `GET /tracker/counts` | `counts` | allowed |
| `POST /tracker` | `add` | allowed (a write) |
| `POST /tracker/{selector}/status` | the verb in the body | allowed for `shortlist`, `track`, `applied`, `interviewing`, `reject` (writes) |
| `POST /tracker/{selector}/outcome` | `company-outcome` | refused (spec 093, Open decisions, item 2) |
| `POST /tracker/{selector}/rescore` | `reevaluate` | refused |
| every `/apply/...` route | `tailor`, `cover-letter`, `answers`, `evaluate`, artifacts | refused |
| every `/outreach/...` route | the matching outreach verb | refused |
| `/mail/events`, `/mail/watch` | `gmail-watch` | refused |
| `POST /capture/add`, `POST /capture/add-form` | `add` | default track only: the routes take no `track` parameter |

A route that depends on `ScopeDep` and declares no operation fails a test
that walks the application's routes, so a new route cannot skip the list.

### The tracks routes

| Route | Operation id | Token | Answers |
|---|---|---|---|
| `GET /tracks` | `listTracks` | no | every track, archived ones included, in id order |
| `GET /tracks/kinds` | `listTrackKinds` | no | each kind, whether a new track of it may be added, and the domain's reason when not |
| `POST /tracks` | `addTrack` | yes | 201 and the new track; 409 for a duplicate slug or a second industry track; 422 for a malformed slug or an unknown kind |
| `POST /tracks/{slug}/archive` | `archiveTrack` | yes | the archived track; 404 unknown; 409 for the default track or one already archived |

`TrackOut` holds `id`, `slug`, `kind`, `label`, `archived`, `is_default`,
and `status_labels`, the kind's label for each of the six statuses from
`KIND_RULES` (spec 093). The browser never holds its own copy of the labels.

The routes call `add_track`, `archive_track` and `list_tracks`, the functions
`harrier tracks` calls, and a test drives both surfaces through them, in the
shape spec 042 established.

### Jobs carry their track and deadline

`JobOut` gains:

- `track`: the slug of the row's track.
- `deadline`: an ISO date, or an empty string for none.
- `deadline_passed`: true when the deadline is before the server's date. The
  server decides, so a browser on another clock cannot disagree with the
  queue the server ordered.

`AddJobIn` gains `deadline`, an optional ISO date, refused with 422 when it
is not a real date. On the industry track it is stored and shown and does not
reorder the queue, as on the command line.

### The browser

**The selected track lives in the URL.** The `track` query string of the
page holds the slug; absent means the default track. A reload, a bookmark or
a second tab therefore shows the same track. Switching tracks changes the
URL and nothing else, so the browser's back button returns to the previous
track.

**No cache crosses tracks.** Every data hook's query key starts with the
selected slug, so a response fetched for one track is never shown in
another, and switching does not wait on a stale one.

**The switcher** sits in the header beside the health badge. It lists live
tracks by label with their kind, marks the selected one, and links to the
tracks page. Archived tracks appear on the tracks page, not in the switcher.
A track named in the URL that no longer exists shows a plain message and a
link back to the default track, rather than an empty table.

**The tracks page** lists every track with its slug, kind, label and state.
It adds a track with a slug, a label and a kind; the industry option is shown
disabled with the reason the domain gives, so the page never offers what the
API refuses. It archives a non-default track after a confirmation that names
the track and says archiving cannot be undone.

**The tracker page on an academic track** shows each status by its label
(`found`, `preparing documents`, `submitted`, `closed`), a deadline column,
and a passed deadline flagged in words, never by color alone. The queue view
shows the server's order and does not re-sort it, as spec 042 already pins
for the industry queue. The add form gains a date field for the deadline.
Status changes offer the verbs the allowlist allows and no company-outcome
control.

**Sections that cannot work on the selected track** are shown disabled with
one sentence: "Not available on <label>: it uses the default track's
profile and configuration." Hiding them would make the browser look like it
covers less than it does on the default track, which is the defect spec 042
names.

## Failure modes

- **A request for an unknown track.** 404 naming the slug. The browser shows
  the message and the link to the default track.
- **A request outside the allowlist on a non-default track.** 409 naming the
  operation and the track, before any row is read.
- **A write on an archived track.** 409 naming the track.
- **A track archived in another tab.** The next write from this tab answers
  409; the browser shows it in the domain's words and refreshes the tracks
  list.
- **An old browser bundle without the parameter.** It reads the default
  track, as it does today.
- **The bookmarklet.** Unchanged, default track only.

Must not introduce: a second copy of the allowlist; a route that reads rows
without declaring its operation; a label or next-action table in the web
app; a query cache shared across tracks; a company-outcome control on a
non-default track; any change to the industry track's responses other than
the three new `JobOut` fields; a track parameter on the capture routes.

## Honest limitations

- **Track slugs and labels are readable without the token, and travel in
  URLs.** `GET /tracks` answers without it, as `GET /jobs` does, and the
  slug sits in the page URL and every API query string, so it reaches
  browser history and the local server's access log. Both are on the
  operator's machine and never in git. A slug and a label are typed by the
  operator; the tracks page says to keep them generic, since they are not a
  place for anything the operator would not want in a URL.
- **The academic track still has no profile, no artifacts and no outreach in
  the browser,** because it has none on the command line. The disabled
  sections say so; they are not a promise of a date.
- **The selected track is per URL, not per user.** There are no users
  (ADR-012). Two tabs on two tracks is a supported state, not a conflict.
- **`deadline_passed` uses the server's date,** which is the container's.
  A container clock that is wrong is wrong everywhere at once, which is the
  better failure.
- **Runs started from the browser are all outside the allowlist,** so
  `RunParams.track` (spec 093) still has no caller. The first run kind a
  non-default track may start is a later spec.

## Migration

None for data. After it ships, `just container-up` so the image carries the
routes and the bundle.

## Options weighed

- **A header instead of a query parameter** for the track. Rejected: a header
  is invisible in the generated contract unless declared on every route, and
  a query parameter is what a bookmarked URL can carry to the API unchanged.
- **The track in the path** (`/tracks/{slug}/jobs`). Rejected: it doubles
  every route and breaks every existing client, for a value most requests
  leave at its default.
- **Hiding sections the track cannot use.** Rejected for the reason in
  Behavior.
- **A router library for the selected track.** Rejected for this change: the
  app has no router (`apps/web/src/app/App.tsx`), and the query string is
  enough. A router is its own decision.

## Open decisions for Akin

1. **Company outcomes on an academic track.** Still refused here, because
   spec 093's Open decisions, item 2, is undecided. Recommendation: allow
   it in both surfaces in one change, since a committee's reply is the
   academic equivalent and reads no profile.
2. **Showing the deadline field on the industry add form.** Recommendation:
   no; the CLI accepts it everywhere, but nothing on the industry track reads
   it, and an unused field invites a wrong guess about what it does.

## Out of scope

- Commands the browser cannot run yet on any track: spec 095.
- Configuration, host-only commands and the CLI-only list: spec 096.
- Per-track profiles and configuration, and any run on a non-default track.
- Renaming a track, changing its kind, or unarchiving it.
- A router library.

## Amendment (2026-10-08, during implementation)

- **`apps/web/PRODUCT.md` joins the Scope.** The design work on this branch
  starts with `/impeccable init`, which writes the product record later
  design work reads: users, purpose, the four commitments every screen keeps
  (never invents claims, nothing auto-sends, data stays local, honest about
  gaps), WCAG 2.2 AA, keyboard-first. It is public, describes the operator
  generically, and is classified public by not matching any never-in-git
  pattern in `config/data-classification.json`.
- **Usable at phone width.** Desktop is the target, and the phone must not
  be broken: a new acceptance criterion holds the changed screens to it.
- **`interviewing` is allowed over HTTP on a non-default track,** as it is on
  the command line: the status route checks the verb in its body against the
  one shared list, and `interviewing` is on it. The table under Behavior
  listed the browser verbs without it; corrected
  (`services/api/tests/test_api_tracks.py::test_routes_outside_the_allowlist_refuse_a_non_default_track`
  is the walk that holds the list).
- **A request without the token is 403,** the answer `require_token` already
  gives every route (spec 035).
- **The industry kind's labels are the browser's words.** The browser held
  its own status words ("CV requested") in two places, and Behavior forbids
  a label table in the web app. `KIND_RULES["industry"]` now carries those
  words, so the industry track reads as it always did and the browser holds
  no copy. The command line prints the stored status on the industry track,
  so its output is unchanged. Spec 093's test that the industry labels equal
  the statuses now holds the one exception
  (`services/api/tests/test_tracks_cli.py::test_status_labels_follow_the_track_kind`).
- **`GET /tracks/kinds` joins the tracks routes.** The add form shows the
  industry option disabled "with the reason the domain gives", and only the
  domain had that sentence. `kind_refusal` in `harrier.tracks` now gives it,
  `add_track` raises with it, and the route reports it, so the form shows
  the words `POST /tracks` refuses with
  (`services/api/tests/test_api_tracks.py::test_the_tracks_routes_list_add_and_archive`).
- **"Every data hook" means every hook that reads a track's data.** The
  tracks list, the kinds, the service's health and a run read by its id are
  the same answer on every track, so their keys do not start with a slug.
  The cache walk in `apps/web/src/app/App.test.tsx` names exactly those four.
- **Apply and runs on a non-default track.** Apply is per row, not a
  section, so each row keeps an Apply control marked unavailable that shows
  the sentence under Behavior when pressed. The run panel on the tracker
  page is replaced by the same sentence, since no run kind is on the shared
  allowlist (Honest limitations).
- **An archived track is read-only in the browser.** Its tracker shows its
  rows with no add form and no row actions, and says it is archived, since
  every write would answer 409.
- **The job table stacks below 900px, not only on a phone.** Its columns
  need about 900px, so between phone and desktop width the actions column
  was cut off inside its scroll box. Below that width each row is a stacked
  record on both tracks. The title and source lines in a job cell are also
  bounded to the cell, which fixes a long title running into the next
  column on the industry table too.
