# Spec 095: Every command that works on the operator's data can be run from the browser

## Problem

Specs 042, 047, 048, 049 and 050 give the browser a route for most of the
commands that work on the operator's data. Several commands arrived after
them, or fell between them, and still have no route:

| Command | Arrived with | Today |
|---|---|---|
| `events show` | spec 079 | terminal only |
| `events backfill` | spec 079 | terminal only |
| `brief show`, `brief set` | spec 066 | terminal only; `set` reads a host file |
| `check`, `check --link-contacts` | specs 036 and 041 | terminal only |
| `evaluate-prospects` | spec 015 | terminal only |
| `scoring export` | spec 077 | terminal only |
| `discover` with its options | spec 011 | the browser starts discovery with no options at all |

Each one is a decision the operator makes about their own data, and each one
today means leaving the browser for a terminal, typing a command whose flags
they have to remember, and coming back. The run machinery, the token, the
route-to-function pairing test and the contract discipline already exist;
these commands only lack routes and a place on a page.

Two of them take a host file (`brief set --file`, `discover --dataset-file`
and its two siblings). The container cannot see host files (spec 074), so the
browser needs a way to supply their contents instead of a path.

## Scope

**API** (`services/api/src/harrier_api/`)

- `app.py` and a new `ops_routes.py`: the routes in the table under
  Behavior.
- `runs.py`: `ParameterizedKind` gains closed-choice flags (a flag whose
  value must be one of a fixed set) and more than one input file per kind,
  and three kinds join `PARAMETERIZED_KINDS`: `events-backfill`,
  `evaluate-prospects` and `scoring-export`. `discovery` becomes
  parameterized. `KIND_COMMANDS["discovery"]` stays as the no-option form
  `POST /runs` already starts.
- Request and response models for each route, in the module that declares
  the route.

**Domain**: none. Every route calls the function the CLI verb calls, named in
the table. If one of those functions needs a parameter the CLI passes
implicitly, the change is a signature change with the CLI updated to match,
never a second implementation.

**Contract**: `packages/contract/openapi.json` and
`packages/contract/src/schema.d.ts`, regenerated by `just contract`. A
guarded path, approved under this spec.

**Web** (`apps/web/src/`)

- `features/tracker/`: a History disclosure on each tracker row.
- `pages/apply/` and a new `features/brief/`: a Brief panel on the Apply page.
- `pages/operations/` (spec 050's page, which this spec extends): sections
  for data checks, decision history, batch evaluation, the learned-score
  export, and discovery's options and uploads.
- Tests beside each changed file.

**Not touched**: the schema, the domain, the CLI's behavior, the tracker,
Apply, Outreach and Inbox routes that exist, and anything spec 096 owns.

## Behavior

### Routes

| Route | CLI verb | Domain function | Shape | Token |
|---|---|---|---|---|
| `GET /tracker/{selector}/events` | `events show` | `list_events` | request | no |
| `POST /ops/events/backfill` | `events backfill` | `backfill_events` | run | yes |
| `GET /apply/{selector}/brief` | `brief show` | the brief reader | request | yes |
| `PUT /apply/{selector}/brief` | `brief set` | `store_brief` | request | yes |
| `GET /ops/check` | `check` | `check_rows`, `unresolved_links` | request | yes |
| `POST /ops/check/link-contacts` | `check --link-contacts` | `backfill_job_ids` | request | yes |
| `POST /ops/evaluate-prospects` | `evaluate-prospects` | `evaluate_prospects` | run | yes |
| `POST /ops/scoring/export` | `scoring export` | `export_features` | run | yes |
| `POST /ops/discover` | `discover` | `run_discovery` | run | yes |

Every route resolves its scope through spec 094's `ScopeDep` and declares its
operation. `events show` is in the non-default allowlist and works on any
track; every other route here is the default track's and answers 409 on
another, as spec 094 states.

The brief reads require the token although they are reads, for spec 047's
reason: a brief holds the operator's own notes about an application, the
densest personal content on the Apply page. `GET /ops/check` requires it
for the same kind of reason: an unresolved contact link is reported by the
contact's name or profile URL, so the check lists contact identities, which
`GET /outreach/contacts` already keeps behind the token. History does not
require it: its free text (`reason_text`) is the same class as the `notes`
and `rejection_reason` that `GET /jobs` serves without the token, which is
the asymmetry spec 047 states and accepts for tracker reads.

Decision history backfill, batch evaluation, the scoring export and discovery
are runs: each walks the whole tracker, calls a model, or reaches the
network. The rest are small reads and writes and answer as requests, which
is spec 042's rule.

### Defaults that change nothing

| Route | Field | Default | What the default means |
|---|---|---|---|
| `POST /ops/events/backfill` | `dry_run` | `true` | Print the counts per kind, actor and code, and write nothing. Writing is the explicit `false`. |
| `POST /ops/check/link-contacts` | `confirm` | `false` | Refuse with 409. Linking edits stored contacts. |
| `POST /ops/evaluate-prospects` | `apply` | `false` | Evaluate and report verdicts; reject nothing. As on the command line. |
| `POST /ops/evaluate-prospects` | `threshold`, `limit`, `refresh`, `include_borderline` | the CLI's defaults | One definition of each default, the CLI's. |
| `POST /ops/discover` | `dry_run` | `false` | As `POST /runs` with kind `discovery` does today. The browser has started discovery for real since spec 006; this keeps that meaning. |
| `POST /ops/discover` | `notify` | `true` | As the CLI. `false` is `--no-notify`. |
| `POST /ops/discover` | `only_source` | absent | Every source. A value outside `SOURCE_ORDER` is 422. |
| `POST /ops/discover` | `apify_count` | the configured count | Bounded as spec 035 bounds it. |
| `POST /ops/discover` | `shadow` | `false` | `true` implies a dry run, as the CLI's `__post_init__` does. |

`--scheduled` is not offered: it selects the schedule's policy, and a browser
click is not the schedule.

### Content instead of host paths

- **The brief is a JSON body,** validated by the store's own checks. An
  unknown key or a wrong type is 400 with the store's message, as spec 023
  answers a bad configuration value. Nothing reaches argv, because brief set
  is a request that writes the document, not a run.
- **Discovery's three files are uploads.** `dataset_file`, `wellfound_file`
  and `wttj_file` arrive as multipart uploads, at most 5 MB each (413
  above it). Each is written to the run-scoped input directory with spec
  047's owner-only mode, its path passed with `--flag=path`, and removed when
  the run ends. No browser-supplied path ever reaches argv.

### The pages

**Tracker: history.** Each row opens a History disclosure listing its events
in order: when, kind, actor, the move, the code and its label, the reason
text, and the score the candidate saw. A backfilled event is marked as
reconstructed, so a reader does not treat its time as the decision time
(spec 079). On an academic track the moves read with that kind's labels.

**Apply: brief.** A panel for one job showing the brief as fields, not JSON:
names never to write, the letter and answer limits, employer guidance and its
URL, evidence entries, views per question, and the compensation number. It
saves the whole brief in one request and shows a refusal in the store's
words, keeping the operator's input in the form.

**Operations: data checks.** The invariant breaches `check` reports and the
contact links that resolve nowhere, each as a list in the domain's words,
with "Nothing to report" when both are empty. Linking contact ids is a
second, separate action that names how many links it would write and asks
for the confirmation the route requires.

**Operations: decision history.** A dry backfill first, showing its counts;
writing is a separate action that names the count it will write.

**Operations: batch evaluation.** A run that reports verdicts. Rejecting is a
second run with `apply` set, offered only after a dry run, naming how many
prospects it would reject and that those rejections are recorded as the
system's decisions (spec 079).

**Operations: learned score.** The export as a run, with its counts when it
ends. Training needs scikit-learn, which the image does not install, so it
stays on the host; spec 096 shows the command.

**Operations: discovery.** The options in the table above, and the three file
inputs. The run streams on the existing run panel.

## Failure modes

- **A dry run's counts are stale by the time the operator applies.** The
  write recounts and reports what it actually wrote; the confirmation names
  the earlier count only as a preview.
- **Evaluation fails for one prospect** (the provider refuses, a timeout).
  Counted as an error in the run's summary and shown; the run continues, as
  the CLI does.
- **The scoring export has nothing to label.** The run ends with the counts
  and the excluded reasons, not an error the operator cannot read.
- **A second run of the same kind while one is active.** The active run is
  returned, as ADR-004's policy says.
- **An upload larger than the cap, or not valid for its importer.** 413
  before anything is written; an unreadable file fails the run with the
  importer's message.
- **A brief that fails validation.** 400 with the store's message; nothing
  stored.
- **A non-default track.** 409 from spec 094's dependency, for every route
  here except history.

Must not introduce: a second implementation of any command; a browser
supplied path or brief text in argv; a write on an empty body (the backfill,
the link and the rejection are each a deliberate second request); a run for
an operation spec 042's rule says is a request, or the reverse; a route that
skips spec 094's operation declaration.

## Honest limitations

- **Spec 050's page is not built yet.** This spec extends it. Whichever lands
  second carries the merge, and the coverage test in spec 096 holds both to
  the same list.
- **The browser shows a dry run's preview, not a lock.** Between the preview
  and the write another process can change the tracker; the write reports
  what it did.
- **Uploads are bounded but not parsed in the request.** A malformed export
  fails in the run, which is where the importer's message is.
- **Training stays on the host.** The export runs in the container; the
  trainer does not (spec 077).

## Migration

None for data. `just container-up` after it ships.

## Options weighed

- **One generic "run any command" route taking argv.** Rejected: it is the
  argument-injection surface spec 047 closed, and it bypasses the
  route-to-function pairing that keeps the two surfaces from drifting.
- **Reading host files through a new mount.** Rejected: spec 074 keeps host
  paths out of the container on purpose; an upload carries the content
  without widening what the container can see.
- **Brief as a run.** Rejected: setting a brief is one validated write, and a
  run would put its text on disk and in a subprocess for no gain.

## Open decisions for Akin

1. **The upload cap.** Recommendation: 5 MB per file. The batch exports are
   small text files; the cap exists so a wrong file cannot fill the disk.
2. **Whether batch evaluation's apply step needs a typed confirmation.**
   Recommendation: no; it is a second request after a dry run that names the
   count, and every rejection it writes is a system decision the operator
   can reopen (spec 072).
